# Повна інструкція: створення, тестування та встановлення Bash-скриптів в Ubuntu 24.04

Зробімо одну зрозумілу інструкцію для нашої системи, щоб ти міг працювати зі скриптами в різних ситуаціях: створити новий, виправити старий, встановити його в `/usr/local/bin/`, оновити, видалити або відновити після помилки.

Головний принцип: редагуємо вихідний код у `~/Desktop/projects/bash/`, а запускаємо готові команди з `/usr/local/bin/`. Це дозволяє не плутати робочі файли з установленими програмами.

## 1. Як організована система

Робочі проєкти

Тут зберігається код, README та, за потреби, Git-репозиторій.

`~/Desktop/projects/bash/`

```
bash/
├── install-bash-script/
│   ├── install-bash-script
│   └── README.md
├── linux-mood/
│   ├── linux-mood
│   └── README.md
└── count-pdf-pages/
    ├── count-pdf-pages
    └── README.md
```

Установлені команди

Готові до запуску з будь-якої директорії.

`/usr/local/bin/`

```
/usr/local/bin/
├── install-bash-script
├── linux-mood
└── count-pdf-pages
```

Наприклад, ти змінюєш `linux-mood` у VS Code. Ці зміни не потрапляють автоматично до `/usr/local/bin/linux-mood`. Щоб команда використовувала новий код, її потрібно перевстановити.

## 2. Стандартний порядок роботи

Для кожного скрипта дотримуйся такого циклу:

1\. Створити або змінити код

У `~/Desktop/projects/bash/назва/`

2\. Перевірити синтаксис

`bash -n script-name`

3\. Протестувати скрипт

Запустити через `bash script-name` або `./script-name`

4\. Установити або оновити

`install-bash-script script-name`

5\. Перевірити готову команду

`command -v script-name`

Важливо: це стандартний порядок, а не вимога виконувати всі кроки абсолютно щоразу. Наприклад, `chmod +x` не потрібен для перевірки синтаксису або встановлення через наш інсталятор.

## 3. Створення нового скрипта

Припустімо, створюємо `linux-mood`.

### Крок 1. Створити директорію та файл

```
mkdir -p ~/Desktop/projects/bash/linux-mood
cd ~/Desktop/projects/bash/linux-mood
code linux-mood
```

У VS Code встав код, збережи файл (`Ctrl+S`) і переконайся, що він називається саме `linux-mood`, без випадкового розширення `.txt`.

Для Bash-скриптів рекомендований початок:

```
#!/usr/bin/env bash

set -Eeuo pipefail
```

Перший рядок — shebang, який указує, що файл потрібно запускати через Bash. Другий вмикає суворіший режим обробки помилок.

### Крок 2. Перевірити синтаксис

```
bash -n linux-mood
```

- Якщо команда нічого не вивела й завершилася з кодом `0` — синтаксична перевірка пройшла.
- Якщо бачиш помилку — виправ її перед установленням.

За бажанням перевірити код завершення:

```
echo $?
```

Команда `echo $?` показує код завершення попередньої команди. Тому запускай її одразу після перевірки.

### Крок 3. Протестувати без `chmod +x`

Можна запустити так:

```
bash linux-mood
```

Цей спосіб не потребує права на виконання файла. Він зручний для першого тестування.

### Крок 4. Протестувати безпосередній запуск

Якщо хочеш запускати файл саме як `./linux-mood`, спочатку зроби його виконуваним:

```
chmod +x linux-mood
./linux-mood
```

Обидва способи правильні — просто працюють по-різному.

## 4. Якщо забув зробити файл виконуваним

Це якраз той випадок, про який ти запитував.

Уявімо, що ти створив `linux-mood`, але пропустив `chmod +x`.

Що ти хочеш зробити?

Установити через `install-bash-script`

Запустити файл локально як `./linux-mood`

Просто перевірити запуск через Bash

Виконуваність вихідного файла не обов'язкова.

```
install-bash-script linux-mood
```

Інсталятор використовує `install -m 755`, тому сам задає права встановленій копії.

Якщо ти вже встановив інсталятор, найпростіший варіант — одразу виконати `install-bash-script linux-mood`. Якщо він ще не встановлений, дивись розділ 5.

## 5. Перший запуск інсталятора `install-bash-script`

Інсталятор — теж звичайний Bash-скрипт, тому спочатку потрібно підготувати його.

### Крок 1. Перевірити, чи існує файл

```
ls -l ~/Desktop/projects/bash/install-bash-script/install-bash-script
```

### Крок 2. Перевірити синтаксис

```
bash -n ~/Desktop/projects/bash/install-bash-script/install-bash-script
```

### Крок 3. Запустити інсталятор без попереднього `chmod`

```
bash ~/Desktop/projects/bash/install-bash-script/install-bash-script --list
```

Так ти перевіриш список доступних скриптів. Щоб установити сам інсталятор, спочатку зроби це з його директорії:

```
cd ~/Desktop/projects/bash/install-bash-script
chmod +x install-bash-script
```

Потім виконай:

```
sudo install -m 755 \
  ~/Desktop/projects/bash/install-bash-script/install-bash-script \
  /usr/local/bin/install-bash-script
```

Тепер команда доступна глобально:

```
install-bash-script --help
install-bash-script --list
```

Важливо: інсталятор використовує `sudo` лише для запису до `/usr/local/bin/`. Не потрібно запускати самі скрипти через `sudo`, якщо їхня робота цього не вимагає.

## 6. Установлення нового скрипта

Припустімо, файл уже збережено тут:

```
~/Desktop/projects/bash/linux-mood/linux-mood
```

Виконай:

```
install-bash-script --list
```

Якщо `linux-mood` є у списку, установи його:

```
install-bash-script linux-mood
```

Інсталятор:

1. Перевірить наявність вихідного файла.
2. Перевірить синтаксис Bash.
3. Перевірить shebang.
4. Якщо команда вже існує, запитає дозвіл на заміну.
5. Скопіює файл до `/usr/local/bin/` із правами `755`.

Якщо з'явиться запит:

```
The command already exists: /usr/local/bin/linux-mood
Replace it? [y/N]
```

- `y` — замінити встановлену версію.
- `N` або просто `Enter` — не замінювати.

Після успішного встановлення:

```
linux-mood
```

Можна запустити команду з будь-якої директорії, наприклад:

```
cd ~
linux-mood
```

## 7. Як перевірити, що встановилося саме те, що потрібно

Використовуй ці команди:

```
command -v linux-mood
```

Очікуваний результат:

```
/usr/local/bin/linux-mood
```

Перевір права:

```
ls -l /usr/local/bin/linux-mood
```

Очікуваний початок рядка:

```
-rwxr-xr-x
```

Перевір синтаксис уже встановленого файла:

```
bash -n /usr/local/bin/linux-mood
```

А також можна перевірити довідку:

```
linux-mood --help
```

Зверни увагу: якщо команда `command -v linux-mood` показує інший шлях, система може запускати іншу копію скрипта.

## 8. Оновлення вже встановленого скрипта

Це найважливіший повсякденний сценарій.

Наприклад, ти вирішив додати нове повідомлення до `linux-mood`.

1. Відкрий вихідний файл, а не копію в `/usr/local/bin/`:
    ```
    code ~/Desktop/projects/bash/linux-mood/linux-mood
    ```
2. Внеси зміни й збережи файл.
3. Перевір синтаксис:
    ```
    bash -n ~/Desktop/projects/bash/linux-mood/linux-mood
    ```
4. Протестуй вихідну версію:
    ```
    bash ~/Desktop/projects/bash/linux-mood/linux-mood
    ```
5. Установи оновлення:
    ```
    install-bash-script linux-mood
    ```
6. Підтверди заміну, ввівши `y`, якщо інсталятор запитає.
7. Перевір результат:
    ```
    linux-mood
    ```

Не потрібно повторювати `chmod +x` щоразу після редагування. Якщо ти зберігаєш зміни у вихідному файлі, інсталятор сам забезпечить потрібні права для встановленої копії.

## 9. Типові ситуації та їх вирішення

Ситуація A. `Permission denied` під час запуску `./linux-mood`

Причина: файл не має права на виконання.

```
chmod +x linux-mood
./linux-mood
```

Або, без зміни прав:

```
bash linux-mood
```

Ситуація B. `install-bash-script: command not found`

Перевір, чи інсталятор існує у `/usr/local/bin/`:

```
ls -l /usr/local/bin/install-bash-script
```

Якщо ще не встановлений, запускай його через `bash` за повним шляхом, як у розділі 5.

Ситуація C. `Script not found`

Інсталятор очікує конкретну структуру:

```
~/Desktop/projects/bash/script-name/script-name
```

Перевір назву директорії та файла:

```
ls -l ~/Desktop/projects/bash/script-name/
```

Наприклад, директорія `linux-mood` повинна містити файл `linux-mood`.

Ситуація D. `Syntax check failed`

Інсталятор не повинен установлювати файл із синтаксичною помилкою. Запусти перевірку вручну:

```
bash -n ~/Desktop/projects/bash/linux-mood/linux-mood
```

Виправ помилку, збережи файл і повтори встановлення.

Ситуація E. Змінив код, але команда поводиться по-старому

Найімовірніше, зміни є лише у вихідному файлі. Повтори встановлення:

```
install-bash-script linux-mood
```

Якщо сумніваєшся, порівняй файли:

```
diff -u \
  ~/Desktop/projects/bash/linux-mood/linux-mood \
  /usr/local/bin/linux-mood
```

Якщо команда `diff` нічого не виводить, файли однакові.

Ситуація F. `install-bash-script --list` не показує скрипт

Перевір, чи файл має правильну назву та розташування. Інсталятор шукає Bash-скрипт із назвою, що збігається з директорією, і Bash-shebang на першому рядку.

```
head -n 1 ~/Desktop/projects/bash/linux-mood/linux-mood
```

Ситуація G. `command -v` показує неочікуваний шлях

```
type -a linux-mood
```

Ця команда покаже всі знайдені варіанти команди. Перевір, чи немає іншої копії або alias, що перехоплює назву.

## 10. Видалення встановленого скрипта

Якщо скрипт більше не потрібен, можна видалити лише його встановлену копію:

```
sudo rm -i /usr/local/bin/linux-mood
```

Параметр `-i` попросить підтвердження перед видаленням.

Це не видаляє вихідний код із `~/Desktop/projects/bash/linux-mood/`. За потреби ти зможеш установити його знову:

```
install-bash-script linux-mood
```

Якщо хочеш видалити весь проєкт, спочатку переконайся, що він більше не потрібен і що код збережений у Git або резервній копії. Не видаляй робочу директорію лише тому, що прибрав команду з `/usr/local/bin/`.

## 11. Як правильно працювати з README та Git

У кожному проєкті бажано мати:

```
linux-mood/
├── linux-mood
├── README.md
└── .gitignore    # за потреби
```

У `README.md` варто описати:

- призначення скрипта;
- вимоги та залежності;
- локальний запуск і тестування;
- встановлення через `install-bash-script`;
- приклади використання;
- доступні параметри;
- порядок оновлення та видалення.

Якщо проєкт використовує Git, після перевірки змін можна виконати:

```
git status
git add linux-mood README.md
git commit -m "Add Linux mood script"
```

Ці команди потрібно запускати всередині Git-репозиторію. Не обов'язково створювати окремий репозиторій для кожного маленького скрипта відразу, але якщо ти хочеш вести історію змін, такий підхід цілком доречний.

## 13. Фінальний чекліст перед установленням

Перевірка готовності

### 0/7

Вихідний файл збережений у правильній директорії.

Назва файла збігається з назвою директорії.

Скрипт має правильний Bash-shebang.

Перевірка bash -n не показує синтаксичних помилок.

Я протестував скрипт і його аргументи.

Я перевірив, що скрипт не виконує небажаних дій.

Я готовий підтвердити заміну, якщо команда вже встановлена.

### Найголовніше, що варто запам'ятати

- `bash -n script-name` — перевірка синтаксису, не потребує `chmod +x`.
- `bash script-name` — запуск через Bash, також не потребує `chmod +x`.
- `./script-name` — безпосередній запуск, потребує права на виконання.
- `install-bash-script script-name` — наш інсталятор перевіряє файл і встановлює його з правами `755`; попередній `chmod +x` для вихідного файла не потрібен.
- Після зміни коду потрібно повторно встановити скрипт, щоб оновилася команда в `/usr/local/bin/`.

І ще одна важлива деталь: успішний `bash -n` підтверджує лише коректність синтаксису, а не те, що скрипт логічно працює правильно. Саме тому перед установленням ми також запускаємо й тестуємо його.
